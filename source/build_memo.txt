保守用メモ（次に手を入れる人向け）

■ ビルド環境
Python 3.14.7
依存パッケージ: requirements.txt 参照（openpyxl）

■ .exe の作り方
1. pip install -r requirements.txt
2. pip install pyinstaller
3. python -m PyInstaller --onefile --name 日次売上サマリ aggregate.py
4. dist/日次売上サマリ.exe を 納品物/ 直下（data・output と同じ階層）にコピーする

■ パスの扱いについて（重要）
aggregate.py は「.exeとして実行されているか」を sys.frozen で判定し、
実行ファイル自身がある場所を基準に data/ と output/ を探す仕組みになっている。
そのため .exe は必ず data/・output/ と同じ階層に置くこと。
場所を変えると動かなくなる。

■ 定休日（データ欠落）の扱いについて
店Aは毎週水曜が定休日で、CSVにその日の行が存在しない（クライアントに確認済み・意図的な仕様）。
これを「0円」や「単純に無視」で処理すると、前日比較が誤った数字になる（実際に検証中に一度、
定休日の翌日を対象日にした際に -18%という誤った急落表示が出るバグがあった）。
対応として、対象日にデータが無い店舗は、当日・比較日の両方から除外して集計している
（compute_summary関数のactiveフィルタ部分）。
別の店舗にも今後定休日が発生する場合、同じ仕組みがそのまま使える。

■ 店舗を追加する場合
STORES リストに {"label": ..., "filename": ..., "encoding": ..., "closed_weekdays": [...]} を
1件追加するだけでよい。closed_weekdays は月曜=0〜日曜=6の整数リスト（定休日が無い店は[]）。
列の順番・日付の書式（YYYY-MM-DD または YYYY/M/D）が既存の想定と違う場合は、
normalize_date の DATE_FORMATS に書式を追加する必要がある。

■ 定休日とデータ未着の区別について（2026-09-06 追記）
初期実装では「対象日にデータが無い」＝「定休日」と一律扱っていたが、これだと店が
単に送り忘れただけの日も「定休日」と表示されてしまい、実際に店Bのデータを1行
欠落させて検証したところ異常な増減率が警告無しで出力される不具合があった。
現在は closed_weekdays（曜日固定の既知の定休日）に一致する場合のみ「定休日」、
それ以外の欠落は「データ未着」として区別し、レポート上部に赤字で警告を出す
仕組みに直した（compute_summary / write_report 内の「状態」フィールド）。
