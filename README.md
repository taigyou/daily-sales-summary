# 日次売上サマリ集計ツール

複数店舗から届く形式のバラバラなCSVを自動集計し、前営業日比較付きのレポートをExcel形式で出力するツール。発注者のPCにPythonが入っていない前提で、`.exe`単体で配布できる形にしている。

## 背景

3店舗の売上CSVを毎朝手作業で集計していた業務（1日あたり約30分）を自動化したいという依頼。要件は「3店舗合計」と「前営業日比較」が分かるファイル出力のみだったが、実データを確認すると以下の課題があった。

- 店舗ごとに列の順番・日付形式・金額の表記（`¥1,234`形式か数値か）・文字コード（UTF-8 / Shift_JIS）がすべて異なる
- 1店舗だけ特定の曜日にデータ行が存在しない（定休日）
- 発注者のPCは実行環境としてPythonが入っていない想定

## やったこと

- ヘッダー名指定でのCSV読み込み（列の位置ではなく列名で参照し、店舗ごとの列順違いを吸収）
- 店舗別に固定したエンコーディング指定、金額文字列のクリーニング処理、日付形式の複数パターン対応
- 「前営業日」を単純な「日付-1」ではなく、各店舗ごとに直前で実際にデータがある日として算出するロジック
- PyInstallerによる`.exe`化と、実行ファイル自身の配置場所を基準にする相対パス解決（`sys.frozen`分岐）
- Excel出力の体裁調整（太字の合計行、金額・パーセント表示の書式、マイナス値の赤字表示）

## 開発中に見つけて直した不具合

1. **前日比較の母数ズレ**: 定休日の店舗を比較対象から片側だけ除外していたため、実際には問題ない日が「-18.1%の急落」として表示される不具合があった。両側から除外するよう修正し、計算の整合性を検証した
2. **配布後のパス解決**: 開発時の相対パスのままだと、`.exe`をどこに配置しても動かなくなる問題。実行ファイル自身の位置を基準にするよう修正した
3. **「定休日」と「データ未着」の区別漏れ**: 納品後にレビューをかけたところ、曜日固定の定休日以外でデータが欠落した場合（送り忘れなど）も一律「定休日」と表示され、異常値が警告なしで出てしまう設計漏れが見つかった。既知の定休日と原因不明の欠落を区別し、後者は警告表示する形に修正した
